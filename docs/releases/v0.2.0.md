This release consolidates the original 0.1.0 public baseline with the
subsequent real-host verification and release-hardening work. It is still an
early release, but the tested surface is substantially broader and the
remaining native behavior is now an explicit compatibility boundary.

The packaged manifest requires host release `0.1.87` or newer and no longer
uses the obsolete experimental manifest flag.

The 0.1.87 release-floor pass also fixes retained gameplay stacks: the
source-owned overworld is preserved as a backdrop while every labelled clean
menu/submenu state is prepared and suppressed through its V3 presenter. This
keeps the drop-in package compatible with the released launcher without
modifying or rebuilding the host.

The sync and release scripts use built-in .NET SHA-256 checks so the launcher
archive can be built from the stock Windows PowerShell command path even when
its optional utility module is not auto-loaded.

The shared V3 contract API now supports `all_generations = true` for one
generation-neutral registration covering both Clean UI products; manifests
still declare launcher eligibility explicitly.

The settings shell now uses the V3 session-local option fallback on the
read-only v0.1.86 options surface. Pointer/touch remains implemented as
low-priority V3 groundwork, but its setting is hidden and the runtime path is
disabled by default because click behavior is incomplete across screen
families. The released host includes both `input.pointer` and `mod.input:tap`,
so this can be revisited without a host modification.

## Baseline carried forward from v0.1.0

- Stable Gen II battle menus, move selection, message frames, responsive
  battle envelopes, palette-aware sprites, and metadata-rich status cards.
- Exact-contract presenters for the audited 0.3 families, production Gallery
  integration, fail-open native fallbacks, and headless CI validation.

## Real-host verification since v0.1.0

- The host integration uses the V3 `render.ui.prepare`,
  `screen.render_visible`, and `render.hud` seams around native screen
  composition, allowing Gen2 presenters to prepare a complete replacement
  frame before `screen.render_visible` suppresses the source UI. Bryan's
  v0.1.86 host exposes `mod.options:define/get` but not `mod.options:set`;
  Clean UI now uses the shared V3 session-local fallback for settings edits
  and Reset Defaults on that supported public surface, while native writers
  remain preferred when a later host provides one.
- Bryan's v0.1.86 host also predates `mod.ui.isBuiltinScreen`. Official Gen2
  identity validation treats that predicate as optional: newer hosts still
  receive the additional class check, while v0.1.86 uses the exact stamped
  `screenId`, source registry ownership, and native draw-override guard. This
  keeps official-screen replacement compatible with the released host.
- The same v0.1.86 fallback is covered against all 51 official screen records,
  not only the main-menu fixture. The legacy `screen.render_visible` hook now
  resolves the live `game` from the state object, keeping Party, Battle,
  Pokegear, dialogue, and pointer/touch replacement on one compatibility path.
- Restored Party and Battle overrides on unmodified v0.1.86 launchers. That
  public host predates the newer generated-image helper, so the drop-in mod
  now uses the host's sandboxed graphics loader only for validated generated
  PNG assets. Newer hosts continue to use their source-image facade and cache
  ownership. No `gen1recomp` patch or rebuild is required.
- The V3 runtime now invalidates its completed canvas on `screen.pushed` and
  `screen.popped`, preventing a closed or replaced UI from surviving into the
  next HUD composition pass when the older host skips the newer prepare seam.
- Gold-host menu smoke covers boot/menu, Start Menu, Party, Pack, Pokegear,
  Trainer Card, Pokedex, Options, Save, PC/storage, clock setup, and Fly Map.
- Battle smoke covers trainer intro and sprite scaling, battle Pack refusal and
  return behavior, forced-switch Party behavior, catch flow, native move
  animations, REVIVE, ETHER, faint flow, and forced switching.
- The post-catch nickname path opens the Clean UI naming keyboard and retains
  the entered nickname in the settled party record; full-party catches land in
  the active PC box without disturbing the party.
- Progression smoke covers the native EXP-bar crawl through level-up, move
  learning, evolution completion and B-cancel, summary pages, egg hatch,
  naming, trade-item display, and TAKE-to-bag behavior.
- An ephemeral no-write route replay reaches the Champion and Hall of Fame
  boundary from the untouched Gold slot with no harness teleports, route-loop
  give-ups, or route failures; the source save remains unchanged.
- Save veto behavior and the canonical Hall of Fame writer are guarded by host
  tests so visual verification does not silently mutate the user's save.

## Validation and release hardening

- Scaffold validation is CRLF-safe and checks the exact catalog, presenter
  inventory, contract coverage, and manifest metadata.
- The release archive is rebuilt twice in an isolated copy and checked for
  deterministic hashing, root containment, manifest ordering/version, and
  required vendored-core entries.
- Versioned curated blurbs live in `docs/releases/vX.Y.Z.md`; the release
  workflow now injects the matching blurb, commit range, and archive SHA-256
  into the GitHub release automatically.
- The Gen1 and Gen2 local launcher sync helpers now replace their exact mod
  targets after validating the expected `%APPDATA%/pokemon-love2d/mods`
  parent, preventing stale files from surviving a development sync. Gen2 also
  mirrors the exact tree into the sibling Grandma's Kitchen source checkout
  when present, because its `Play-Gen2-Clean-UI-Dev.cmd` resolves the local
  source `mods/` tree before the AppData install.
- Local visual-audit captures remain available for testing but are excluded
  from Git; release notes describe verified behavior rather than packaging
  screenshots.

## Deliberate scope boundary

Battle-owned child stacks and some native animation primitives remain native
where replacing them would risk gameplay behavior. The pre-battle transition,
in-battle intro, animation-state surfaces, and Evolution cinematic are
represented by Clean UI, while source timing and unproven child stacks remain
fail-open around those boundaries.
